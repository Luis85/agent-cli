# Trailhead: The Forge showcase

Trailhead is a small fictional trip-planning web app for hiking groups. This managed Forge project shows The Forge's capabilities end to end: an Obsidian-compatible knowledge graph of specs and docs, Canvas and Bases, a product backlog compatible with the Obsidian Product Backlog view, a component library with interactions generated for all seven UI targets with Storybook stories, data sources with typed adapters and fixtures, domain and application code, forms, a native Claude agent, agent skills and the project's own CI workflow.

Everything here is generated by the bundled CLI. The Forge project's `scripts/showcase.mjs` (in `src/the-forge`) drives `node bin/forge.js` with fixed inputs and the fixed date 2026-10-10T09:00:00Z, so regeneration is byte-for-byte reproducible. Do not edit generated files by hand; change the script and regenerate.

## Browse, regenerate and verify

- **Obsidian:** open `src/forge-showcase` as a vault and start at [docs/Trailhead.md](<docs/Trailhead.md>). Opening the whole repository as a vault also works, but Canvas file paths are relative to this project folder.
- **Regenerate** from `src/the-forge`: `npm run showcase`. **Check drift:** `npm run showcase:check` regenerates into a temporary workspace and lists differing paths.
- **Project checks** from this directory: `npm ci`, then `npm run check` and `npm test`. The committed `package-lock.json` is refreshed only by `npm run showcase -- --lockfile`.
- **Forge commands** run from the repository root. File commands need this project selected (`node bin/forge.js project open forge-showcase`); restore the checkout's selection afterwards with `node bin/forge.js project open the-forge`. UI and data-source generation accept `--project forge-showcase` without changing the selection.

## Backlog sync

[backlog/Azure DevOps sync.base](<backlog/Azure DevOps sync.base>) binds two `product-backlog` views to two Azure DevOps connections with the view option `connection: <id>`: planning work (Epics, Features, PBIs) syncs to one organization, delivery work (Tasks, Bugs) to another. The connections are workspace configuration, so they are not part of this project; the generation workspace's `bin/config.json` held:

```json
{
  "plugins": {
    "settings": {
      "connector": {
        "connections": {
          "contoso": {
            "platform": "azure-devops",
            "organization": "https://dev.azure.com/contoso-trailhead",
            "project": "Trailhead",
            "process": "agile",
            "iterationRoot": "Trailhead",
            "tokenEnv": "TRAILHEAD_CONTOSO_PAT"
          },
          "fabrikam": {
            "platform": "azure-devops",
            "organization": "https://dev.azure.com/fabrikam-delivery",
            "project": "Delivery",
            "process": "scrum",
            "tokenEnv": "TRAILHEAD_FABRIKAM_PAT",
            "linkProperty": "fabrikam"
          }
        }

  }
```
