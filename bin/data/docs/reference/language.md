# CLI language

[Documentation](../index.md) · Reference

The CLI supports English (`en`, the default) and German (`de`). Select a language for one invocation:

```sh
node bin/forge.js --lang de help
node bin/forge.js help make --lang de
node bin/forge.js --lang en schema --json
```

For a persistent workspace preference, set `settings.language` in `bin/config.json`:

```json
{"settings":{"language":"de"}}
```

Missing settings use English. The explicit `--lang` option overrides the configuration. `config` reports effective settings, including this override; `setup --lang de` writes German as the preference when it creates a missing configuration. Neither command updates an existing configuration. Unsupported values fail with `INVALID_LANGUAGE` for the flag or `INVALID_CONFIG` for configuration. A flag does not bypass invalid configuration: correct the file before retrying.

## What changes

Built-in command and generator descriptions, built-in format/event explanations, setup and empty-library guidance, and actionable error summaries and hints are translated: `error.message` becomes the German summary and `error.hint` the German next step, and `schema` lists German summaries at `data.errors`. Error summaries are selected by stable application codes from the [error catalog](errors.md). The original diagnostic remains at `error.details.localization.originalMessage`, including precise paths, invalid fields and third-party parser messages. Existing error details remain available; if an error already contains a `localization` detail, its value is retained as `error.details.localization.originalDetails`. English retains the original message and detail shape.

Command names, usage syntax, flags, IDs, paths, JSON keys, status values, exit codes and event payloads remain stable in both languages. Scripts should match error codes and structured details rather than translated messages. Generated code, fixture data, component/data-source definitions, Markdown documents, templates and skill contents retain their authored language and identical generated bytes. Plugin metadata, plugin-defined error codes, plugin result data and runtime warnings remain in their original language. Built-in error codes raised by plugins receive the same translated summary while retaining their original diagnostic.

## Errors during discovery

The CLI establishes a language after successfully parsing global prefix options, then reads configuration, then parses the command. Put `--lang de` before the command when German guidance is needed for command-discovery or argument-parsing errors. A language placed after the command applies once command parsing succeeds. A malformed global prefix fails before language selection and uses English. Invalid configuration can be diagnosed in German with a valid prefix `--lang de`; configuration validation still fails normally.

Locale selection does not consult operating-system locale variables, so invocations remain reproducible across machines.
