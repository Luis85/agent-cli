# The Forge workspace

This repository is a Forge workspace: a thin root that ships the portable CLI and holds self-contained managed projects under `src/`.

The Forge is a terminal project companion for AI-assisted project and product development. The user lives in Obsidian, where design, concepts, specifications, documentation and code are managed. The AI agent gets its own CLI to the same vault. With it, the agent can do anything the user can do in Obsidian, without Obsidian running or installed. Everything is stored as Markdown, Canvas and Bases, linked into one knowledge graph. Git backs it, and every write can be verified deterministically. Read the [product vision](src/the-forge/docs/explanation/product-vision.md).

| Path | Contents |
| --- | --- |
| `bin/` | The shipped portable CLI/server from `src/the-forge` and prebuilt admin assets from `src/forge-admin`. Run `node bin/forge.js --help`. |
| [`src/the-forge/`](src/the-forge/README.md) | The Forge project: its source, toolchain, tests, [documentation](src/the-forge/docs/index.md) and authored agent skills. |
| [`src/forge-admin/`](src/forge-admin/README.md) | Independent Vue and Nuxt UI admin webview, with Playwright inspection and browser tests. |
| [`src/forge-showcase/`](src/forge-showcase/README.md) | Trailhead, a fully generated showcase project and Obsidian vault demonstrating every capability. |
| `.github/workflows/` | CI entrypoints generated by `node bin/forge.js workflows sync` from each project's `src/infrastructure/workflows/<concern>/` files. Do not edit them by hand; see [workflows](src/the-forge/docs/reference/workflows.md). |
| `AGENTS.md` | Rules for agents and contributors working in this workspace. |

## Use the CLI

Install **0.1.0** in another repository or a new workspace from [GitHub Releases](https://github.com/Luis85/agent-cli/releases/tag/v0.1.0):

```sh
curl -fL https://github.com/Luis85/agent-cli/releases/download/v0.1.0/install-forge.mjs -o install-forge.mjs
node install-forge.mjs --version 0.1.0 --workspace ./my-workspace
cd my-workspace
node bin/forge.js project create my-project --dry-run
node bin/forge.js project create my-project
node bin/forge.js project open my-project
```

The installer verifies the archive checksum, uses generic defaults and refuses an existing `bin/`. See the [agent installation workflow](src/the-forge/docs/how-to/install.md) for Windows and offline installation. Installation needs Node >=22.12, curl and tar; no npm dependencies or repository source are required.

Requires **Node 22.12 or newer**. The committed `bin/` needs no installation. This checkout manages its own source: tracked `bin/config.json` sets `paths.projects` to `src`, and tracked `bin/data/context.json` selects `the-forge`, so file commands resolve inside `src/the-forge` until you select another project.

```sh
node bin/forge.js project current --json
node bin/forge.js help read --json
node bin/forge.js read src/main.ts --json
node bin/forge.js project list
```

For an agent, the [For AI agents](src/the-forge/README.md#for-ai-agents) quick start sums up the contract. Start with `help <command>` for usage and `schema <command> --json` for the exact input/output contract. `schema --json` alone lists the command ids; use the complete `schema --all --json` only when you need the entire installed catalog. Check both `ok` and the exit status, verify `context.root`, and preview mutations before applying them with the current file revision. The [workflow skill](src/the-forge/skills/forge-workflow/SKILL.md) describes this loop.

To start a new, empty workspace instead, follow the quickstart in [The Forge README](src/the-forge/README.md#use-the-committed-bundle).

## Upgrade the app

The installed app can upgrade itself with `node bin/forge.js update check --json`, followed by a reviewed pinned `update apply --release-version <version> --if-match <revision> --dry-run`. Apply the same command without `--dry-run` after reviewing the changes. It preserves configuration, project selection, plugins, templates and custom webviews; see [app updates](src/the-forge/docs/reference/updates.md).

## Inspect the workspace in a browser

Start the packaged read-only admin view through the CLI:

```sh
node bin/forge.js server start --webview admin --json
```

Open the returned `data.url` to inspect workspace/project context, plugins, contribution counts and runtime health. The server binds only to `127.0.0.1`; the launch link includes a local session token. The CLI does not open a browser or prompt. Repeated startup reuses the running workspace server, and project selection stays unchanged.

```sh
node bin/forge.js server status --json
node bin/forge.js server stop --json
```

The core server is independent of the webview and can serve other packaged views. See [use the admin webview](src/the-forge/docs/how-to/use-admin-webview.md) and the [server contract](src/the-forge/docs/reference/server.md). The [admin project](src/forge-admin/README.md) owns its Vue/Nuxt UI toolchain and Playwright tests.

## Prototype a new webview

```sh
node bin/forge.js project create idea-board --type webview --dry-run
node bin/forge.js project create idea-board --type webview
```

The generated project owns its Vue 3/Nuxt UI source, sample data, build scripts and Playwright tests. Build and test inside that project, then publish with `node bin/forge.js webview publish --project idea-board` and start it with `server start --webview idea-board`. The [prototyping guide](src/the-forge/docs/how-to/prototype-webviews.md) covers the complete loop; the bundled [forge-webviews skill](src/the-forge/skills/forge-webviews/SKILL.md) guides agents through creation, iteration, screenshots and guarded updates.

## Explain a page or flow with screenshots

`browser screenshot <url> --out docs/assets/page.png` captures on-demand webpage evidence. `browser validate <source>` and `browser tutorial <source> --out docs/manual` turn an explicit JSON, Markdown or Canvas flow plan into an illustrated document. The agent reviews the flow, inspects the actual images and explains the observed situation in Markdown. See [capture browser evidence](src/the-forge/docs/how-to/capture-browser-evidence.md) and the bundled [forge-browser skill](src/the-forge/skills/forge-browser/SKILL.md).

## Develop a project

Each managed project installs, checks and tests itself from its own directory:

```sh
cd src/the-forge && npm ci && npm run check      # rebuilds the workspace bin/ and runs every test
cd src/forge-showcase && npm ci && npm run check
```

See [develop and verify a change](src/the-forge/docs/how-to/develop-and-test.md) and [explore the showcase](src/the-forge/docs/how-to/explore-the-showcase.md).
